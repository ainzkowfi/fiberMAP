## Map content

At the crew's instruction the app no longer draws any hardcoded geography. The
AH26 corridor (Trento to Bayugan), the Agusan River (Esperanza to La Paz) and the
0.05 degree graticule are all gone. A baked-in route looks exactly like a fibre
line the crew owns, and it was not theirs. Real geography comes from the OSM
basemap archive instead. Only place names remain as local reference points.

## Bugs found while fixing the findings

- The basemap style pointed at `water_polygons` and `water_lines`, but the
  archive's layers are `water` and `waterway`. Water was never rendering.
- Adding the basemap source made MapLibre fit the whole archive into view,
  throwing away the crew's camera and zoom. The camera is now captured and
  restored around the source add.
- `exportedAt: Date.now()` in the bundle made the bundle string change on every
  render. The Share screen's QR effect set state from that string, and the two
  fed each other until React threw "maximum update depth" (#185). The export
  timestamp is now stable state.
- The `hidden` attribute collapsed the MapLibre canvas to 0x0, which made the
  map re-fit itself and scramble the zoom. The map is now hidden with
  `visibility`, so it keeps its size and its decoded tiles.
- The service worker served the previous build after a deploy. A new worker
  taking control now reloads the page, so the crew never runs a stale shell.

## Checked and clean

The findings below are the original write-up, kept as the record of what was
wrong. Each one was fixed, see the fix log at the top.

### 1. Dark mode never reaches the map
**Rule:** R-34 (every theme you ship must work), R-21 (a theme toggle must work in both modes)

`src/ui/mapStyle.ts` bakes the light palette into the MapLibre style: the background layer
interpolates `#e9edef` to `#f4f6f7`, and `PMTILES_STYLE_LAYERS` hardcodes light fills
(`#f4f6f7`, `#a9cfe8`, `#ffffff`) and strokes. Switching to dark mode repaints the chrome
but the map stays light, so the crew gets a light basemap inside a dark app.

Verified: dark mode screenshot shows a light map with a dark header, dark nav bar and a
light-on-light street network.

Fix: rebuild the style on `data-theme` change. The style is one object, so this is a
`setStyle` call plus the two colour sets, not a rewrite.

### 2. `--muted` fails AA on tinted surfaces
**Rule:** R-25 (contrast, minimum 4.5:1 for normal text)

`--muted: #5a6b74` on `--surface-variant: #d7dee3` is **4.08:1**, light mode only.
This is the colour behind `.stat .k`, the 10px uppercase stat labels (MAP DISTANCE, CABLE,
SLACK, CUTS PER KM, AVG MTTR). 10px uppercase is normal text, so it needs 4.5:1.

Measured across the whole palette, every other pair passes in both themes
(dark mode: 5.08:1 on the same pair). Only this one pair fails.

Fix: darken `--muted` until it clears 4.5:1 on `--surface-variant`. No other token moves.

### 3. No modal closes with Escape
**Rule:** R-32 (dialogs must be closable with Escape)

There is not one `keydown` listener in the app. Four surfaces are modal and all four
trap the user:

- Pin detail sheet (`src/ui/PinSheet.tsx`)
- Find by OTDR sheet (`src/ui/OtdrDialog.tsx`)
- Export preview sheet (`src/ui/Share.tsx`)
- Settings and base-map manager overlays (`src/App.tsx`)

On a phone with no keyboard this is invisible, but the same code has to work in a browser
tab on a truck-mounted laptop, where Escape is the reflex.

## MEDIUM (Purpose-Gate and structural)

### 4. Icon-only close buttons have no real accessible name
**Rule:** R-39 (every control needs an accessible name)

The three sheet close buttons render a bare `✕` as their only content:
`PinSheet.tsx`, `OtdrDialog.tsx`, `Share.tsx`. A screen reader announces "multiplication x".
The map's zoom buttons already use `aria-label`, so the pattern exists in the codebase, it
just was not applied to the sheets.

### 5. No `main` landmark
**Rule:** R-39 (landmarks)

The shell has `<header>` and `<nav>`. The region that actually holds the content,
`.app-body`, is a plain `<div>`. Screen reader users get no way to jump to the content.

### 6. Share has no empty state
**Rule:** R-27 (empty, loading and error states)

With no lines and no pins, every export button on the Share tab still produces a file:
an empty `FeatureCollection`, a KML with no placemarks, a CSV with only a header row.
The screen never says the export is empty. The Lines tab has a proper empty state; Share
does not.

### 7. The 9 MB basemap download has no progress feedback
**Rule:** R-27 (loading state), R-35 (a loading state that tells the user what is happening)

The button flips to "Downloading..." and stops there. No bytes, no percentage, no ETA.
On a weak mobile connection the difference between a 9 second download and a 9 minute one
is invisible, and the only way to tell is to wait. `fetch` already reports progress via
`ReadableStream`, and the archive is stored in IndexedDB after, so both phases can report.

### 8. The QR image has no intrinsic size
**Rule:** R-40 (media needs width and height)

`<img src={qrImage} ...>` in `src/ui/Share.tsx` has no `width`/`height`. The frame is
sized in CSS, so the card jumps when the image resolves. The generator knows the size
(512 px) at render time.

### 9. The map's coordinate grid has no written reason
**Rule:** R-07 (background grid needs a stated purpose), R-31 (write the reason down)

`src/ui/MapView.tsx` draws a 0.05 degree coordinate grid over the whole province. The
purpose is real: a crew reading chainage off a map needs a coordinate reference, and the
grid is the only one available offline. But nothing says so next to the layer, so the
next person to touch the map reads it as decoration and deletes it.

The theme header explains the palette. The grid layer needs the same treatment.

### 10. The bottom navigation uses emoji as its icon set
**Rule:** R-04 (icon set chosen for recognizability rather than relevance)

`🗺 📍 ↗` in `src/App.tsx`. They render differently on every platform, they carry no
information the label does not already carry, and the third one (↗) is an arrow used as
decoration, which R-08 also flags. Three small inline SVGs would cost about the same and
would look the same on every phone.

## LOW (Quality Locks)

### 11. Two decisions are documented but not where they are made
**Rule:** R-31 (write the reason down)

The tile schema decisions (why landuse stops at z12, why z15 and not z16) are documented
in `web/basemap/README.md`, which is the right place for them. The app-side decision, that
the crew gets a 9 MB archive rather than the 2 MB one that was already in the repo, is
explained only in the MapManager copy the user reads once. One comment at
`BUNDLED_BASEMAP` in `src/ui/pmtilesStore.ts` would put the reasoning where the number is.

### 12. Every card and list row carries a left-edge stripe
**Rule:** R-14 (feature cards), Part 1 "Colored left stripe"

Found by the impeccable detector (`detect --json`), reported as `side-tab`:

- `src/theme.css:330` `.card` sets `border-left: 3px solid var(--border-strong)`
- `src/theme.css:721` `.list-item` sets `border-left: 4px solid var(--border-strong)`

Both stripes use the neutral border colour rather than an accent, so they are not
colour-coded decoration, but they are still a left-edge emphasis bar on every panel and
every row. In the line list the row already carries a colour swatch for the fibre strand,
so the second stripe says nothing. The stripe on `.card` gives the whole app the
"dashboard card" look the direction is trying to avoid.
