## HIGH

### 1. One uncaught throw blanks the app
**Rule:** R-27 (error state), C-4 (resilience)

There is no error boundary anywhere in `web/src`. Any render throw unmounts the
whole tree and the crew gets a white screen with a browser error, in the field,
with no way to recover except force-quitting.

This is not hypothetical. MapView threw three times during this session's
testing (`Cannot read properties of undefined (reading 'getLayer')`), and each
time the entire app went with it. The Android original had a global crash
handler for exactly this reason.

Fix: one boundary around the app body, with a "reload" action and the error
message. About 20 lines.

### 2. Reassigning a pin to another line leaves a stale chainage
**Rule:** C-1 (intentionality), data integrity

`updatePin` in `src/data/repo.ts` writes `lineId` but keeps the existing
`snapLat`, `snapLon` and `chainageM` from the row it was handed. The pin sheet
lets the crew change "Assign to line", so:

- move a pin from line A (chainage 4+200) to line B and it still reads 4+200 on
  line B
- the map dot stays at the old snapped position, not on line B
- line B's stats and OTDR coil list pick up a chainage that belongs to line A

`dropPin` does the snapping correctly (50 m gate, `snapPointToPolyline`).
`updatePin` does not. The snap belongs in one place, and it is not there.

Fix: when `lineId` changes, re-snap and recompute chainage before writing.

### 3. Sheets are not dialogs
**Rule:** R-32 (keyboard), R-39 (semantics)

The pin sheet, OTDR sheet, export preview and line form are `<div class="scrim">`
with no `role="dialog"`, no `aria-modal`, no focus trap, and no focus restore on
close. A screen reader user hears the page behind them, and Tab walks out of the
sheet into the map controls underneath.

Escape closing them (fixed in audit-001) is only half of R-32.

### 4. The toast is silent
**Rule:** R-39 (accessible feedback), R-27

Every confirmation in the app is a toast: "Pin updated", "Repair logged",
"Basemap stored", "Cut pin dropped at the OTDR location". It has no `role` and no
`aria-live`, so a screen reader user gets no confirmation that anything happened.
For a repair log that is the difference between trusting the record and not.

### 5. The GPS watch runs forever and fails silently
**Rule:** R-27 (error state), R-40 (performance)

`useGpsTracker(true)` in `App.tsx` starts a `watchPosition` on mount and never
stops it. On a field phone that is a continuous radio and a battery drain for an
app that is mostly used to look at a map. The crew can leave it on the seat and
come back to a flat battery.

Worse, `gps.error` is returned by the hook and read by nobody. If the crew
declines the location prompt, the map silently stays wherever it was and nothing
says why. The single most common field failure has no message.

Fix: gate the watch on "is the map or the GPS draw flow active", and surface the
error in the map HUD.

## MEDIUM

### 6. The QR transfer is send-only
**Rule:** R-26 (every control does what it says), R-38 (real content)

The Share screen says "Scan each frame in order on the receiving device", and
`reassembleFrames` exists with tests, but no screen calls it. There is no
receiving device in this app. A crew with two phones can send and never receive.

Either build the receive side (camera or file import of a decoded frame) or
change the copy to say the frames are for an external reader.

### 7. The database backup cannot be restored
**Rule:** R-26, R-27

"Export raw database snapshot" writes lines, pins, events and repair logs. It
omits `settings` and `mapFiles`, and there is no import for it anywhere. The
button produces a file that nothing in the app can read back, so it is a false
safety net for the crew's only copy of their work.

Note the bundle export/import path *is* round-tripped and works. This raw
snapshot is the dead end.

### 8. The maskable icon will be cropped
**Rule:** R-40, PWA correctness

`vite.config.ts` declares `favicon.svg` as `purpose: "any maskable"`. The artwork
puts the cable endpoints at x=7 and x=57 of a 64 unit box. Android's maskable
safe zone is the central 80 percent, so both endpoint dots get cut off on the
home screen. One file cannot honestly claim both purposes without being drawn
for the safe zone.

### 9. Two sources of truth for the same queries
**Rule:** C-1, maintainability

`src/data/repo.ts` exports `getAllLines`, `getAllPins`, `getAllEvents`,
`getAllRepairLogs`, `purgeAll`, `insertLineRows`, `insertPinRows`,
`insertEventRows`, `insertRepairLogRows`. All nine have zero call sites.
`src/data/hooks.ts` does the same job through `useLiveQuery`, which is what the
app actually uses.

Same for `BOUNDS`, `DEFAULT_CENTER`, `DEFAULT_ZOOM` in `reference.ts`,
`LAYER_ORDER` in `MapView.tsx`, and `logManualPoint` in `useGpsTracker.ts`:
declared, exported, never called.

Dead code in a small app is not a style problem. It is how the next person ends
up editing the query that does not run.

### 10. Setting a pin to REPAIRED by hand records no event
**Rule:** data integrity

The pin sheet has state chips (Open / Repaired / Normal) and a separate "Mark
repaired / spliced" button. Choosing "Repaired" in the chips writes
`state: "repaired"` with no `PinEvent`. `calculateLineStats` then counts it as a
repair but has no repair timestamp, so it falls back to `pin.updatedAt` for the
repair and `pin.createdAt` for the cut, and MTTR comes out as the pin's entire
lifetime.

The two paths should not disagree about what a repair is.

## LOW

### 11. `formatChainageKm` is only used by its own test
**Rule:** C-1

`src/core/geometry.ts` exports it, `geometry.test.ts` asserts on it, nothing in
the app calls it. Either the repair log should use it (it is the "Km 2+450" form
that matches the Android repair log) or it should go.

### 12. Two unused CSS classes
**Rule:** C-1

`.field .hint` and `.maplibregl-map` in `theme.css` match nothing in the markup.

### 13. The app shell has no skip link
**Rule:** R-39

There is a `<header>`, a `<main>` and a `<nav>`, which is the structural half of
R-39. A keyboard user on a laptop still has to Tab through the header and the
whole map control stack to reach the list. One skip link to `#main`.
