## What the click-through could not break

The delete itself was never broken. A line with pins and a repair log deleted
cleanly on a 390x844 and a 360x640 viewport, with and without a native dialog
accepted, and the list emptied every time. The line detail's delete button was
reachable after one scroll. That is why the fix is about finding delete and
about not depending on a native dialog, not about the write.

## Checked and clean

- `impeccable detect --json src/` returns `[]`.
- No native `confirm`, `alert` or `prompt` left in the app.
- Every destructive action now goes through one confirm sheet with the same
  wording, and every one of them is an `alertdialog` with focus inside.
- `tsc` clean, 25 unit tests pass, `vite build` clean, `npm run contrast` 0
  failing pairs.
- The full flow was clicked through on the built app: draw, save, long-press
  pin, repair, line delete, pin delete, base map download and delete, snapshot
  export and restore, QR frame import. 0 console errors.

## Known limits

- The Android bundle format is only verified against the web app's own
  exporter. The comment in `exportImport.ts` says the first block matches the
  APK byte for byte; that has not been checked against a real APK export.
- An imported archive with a different tile schema will render empty, because
  the style asks for source layers by name (`water`, `waterway`, `roads`).
  The province archive uses the schema in `web/basemap/schema.yml`.
