## Round 2, same day: tapping a line

Trigger: "clicking the lines should also show the line status and its data in
mini popup bubbles".

| # | Fix | Verified by |
|---|---|---|
| 8 | Tapping a fibre line opened nothing. A line on screen is two or three pixels wide, which no thumb can hit, so the tap now looks in a 28 pixel box around the finger and opens a bubble with the line name, its status, its length, its core count, its pins and its repairs, plus one button into the full record. Escape closes it, and tapping empty ground closes it. | Tap the drawn line: the bubble reads "Sta Maria Feeder / ACTIVE / 0+546 m · 24 cores / 0 pins 0 repairs / Open details". Escape closes it, "Open details" opens the line detail, 0 console errors |
| 9 | **Tapping a pin on the map did nothing.** The map click handler was registered once, when the map was created, and it searched the pin list from that moment. The list was empty then, so the pin was never found. The handler now reads the current pins through a ref. | Long press drops a pin, Escape, then tap the pin on the map: the pin sheet opens. Before the fix the tap fell through and did nothing |

The bubble is a MapLibre popup, so it tracks the camera while the map animates.
Its content is React, mounted in a small root inside the popup, and the popup
uses the app's own surface, border and shadow instead of MapLibre's default
white box.

## Round 3, same day: the line record

Trigger: "each line details/info it has too many data and overwhelming.. remove
slack, cuts/km, avg mttr, last repair isnt needed when reapir log already does
that... redesign it and unslop".

| # | Fix | Verified by |
|---|---|---|
| 10 | The line record answered with nine numbers in two tile grids and carried a second timeline next to the repair log. It now answers with four numbers in one row, divided by hairlines: length, cable, cuts, open. Slack, cuts per km, average repair time and the date of the last repair are gone, and so is the repairs count, because the repair log heading already carries it. The event timeline card is gone: the repair log is the history, and the per-pin history lives in the pin sheet. | The record reads "LENGTH 0+700 m / CABLE 0+721 m / CUTS 1 / OPEN 0", then the strip, the two actions, the notes, the pins and the repair log |
| 11 | The statistics the screen stopped showing were still computed on every line, every render, and still carried in the domain model: average repair time, cuts per km, last repair date, total slack coil length, plus the `formatDuration` and `formatDate` helpers. All of it is removed from the model, the computation and the test. | `LineWithStats` is six fields. 24 tests pass, one of them deleted with the statistic |
| 12 | Pins were labelled with the raw enum, "CUT_REPAIR at 0+268 m", and the detail line under it printed the type and the chainage a second time. A pin is now named by the crew or by its type, the type only appears on the detail line when the crew named it, and the empty label field in the pin sheet shows the name it would get as a placeholder. | The pin list reads "Pole 3 NAP / Cut / Repair · 0+245 m" and "Cut / Repair / 0+589 m · 0.03 dBm". The placeholder reads "Cut / Repair at 0+245 m" |
| 13 | The repair log printed the raw method code, "FUSION". It prints "Fusion Splice". | Log entry: "0.03 dBm · Fusion Splice" |

The reason for every cut: the numbers a crew reads in the field are the length
of the route and the condition of the cable. Everything else is history, and
history belongs in the log where it can be read in order.

## Round 4, same day: place names and the nav

Triggers: "add a feature for adding a name of that place or area name cuz the
map only has municipal names" and "also put settings on the bottom navbar too,
make it mobile touch friendly".

| # | Fix | Verified by |
|---|---|---|
| 14 | The map's only labels were the nine hardcoded municipality names, even though the province archive carries the OSM place names: the `places` layer, z8 to z15, cities, towns, villages, barangays and sitios. The style never asked for that layer, and MapLibre cannot draw text without a glyph server, which would break offline use. The names are now read out of the loaded tiles and drawn as DOM markers, the same way the municipality names are. Bigger places first, quieter styling, capped at forty names, and only from z11 up. | At Sta. Maria the map now shows "Santa Maria" under the GPS dot, next to the nine municipality names |
| 15 | There was no way for the crew to name a place OSM does not know: a purok, a site, a customer's house. There is now a tag button on the map, the crew taps the map where the name goes, writes it, and it stays on the map. Tapping the name opens it to rename or remove it. The names live in IndexedDB (schema version 2) and travel in the bundle export and import. | Name a place -> the banner -> tap the map -> the sheet with the coordinates -> "Purok 7 Tanging" appears on the map. Tap it -> "EDIT THE NAME" -> rename -> "Purok 7 Tanging". Remove -> it is gone. Export -> the bundle carries the name -> import -> "1 names" |
| 16 | The Share screen refused to export when there were no lines and no pins, so a crew with nothing but place names could not get their work out of the app. Names count as work now. | The export button is live with only a place name on the map |
| 17 | The Settings gear sat in the header, at the top of the screen, which is the hardest place to reach with a thumb on a phone held in one hand. It is now the fourth item in the bottom nav, next to the map, the lines and the share. The gear in the header is gone, so there is one way in and not two. | The nav reads "MAP LINES SHARE SETTINGS" with no overflow at 320 px, the settings overlay opens from it and closes with its own back button |

The upgrade path matters more than the feature: the crew's phone already holds
a version 1 database. A database built with the old schema was upgraded in
place, the `placeLabels` table appeared, and the app carried on with no errors.

## Known limits

- The first install now pulls about 11 MB instead of 1.5 MB. That is the
  crew's call and it was made.
- The basemap is only as detailed as OSM is. Sta. Maria shows streets and
  waterways, not addresses or house numbers.
- Geolocation needs https. A phone opening the app over plain http on a LAN
  address gets the message saying so, but it will not get a position.
